# Directory Layout & Host Volume Mounts

This section describes the filesystem layout on the host server under `/docker` and explains how container data persistence is maintained across restarts and upgrades.

---

## 📂 Host Directory Hierarchy (`/docker`)

All persistent data for containers is located under `/docker` on the host Ubuntu filesystem:

```
/docker/
├── appdata/        # Application state, databases, config files
├── custom/         # Custom Dockerfiles and build contexts
├── fail2ban/       # Fail2ban configuration data
├── logs/           # Centralized log storage mounted by services
├── scripts/        # Operational shell scripts and cron tasks
├── secrets/        # Encrypted passwords, keys, and API credentials
└── shared/         # Shared assets used across multiple containers
```

---

## 🗄️ Application Data Breakdown (`/docker/appdata`)

Each service has a dedicated directory inside `/docker/appdata/` to keep data isolated:

| Directory | Container Owner | Contents & Description |
| :--- | :--- | :--- |
| `/docker/appdata/traefik/` | `traefik` | Traefik dynamic rules, `traefik.yml`, and `acme.json` SSL certificates. |
| `/docker/appdata/portainer/` | `portainer` | Portainer database and application configuration. |
| `/docker/appdata/crowdsec/` | `crowdsec` | CrowdSec hub configurations, bouncer keys, and threat database. |
| `/docker/appdata/matrix/` | `matrix_synapse` | Synapse media store, server keys, and configuration. |
| `/docker/appdata/moodle/` | `moodle` | Moodle uploads, courses, and LMS data. |
| `/docker/appdata/wiki/` | `wiki` | MediaWiki upload directory and LocalSettings.php. |
| `/docker/appdata/wikijs/` | `wikijs` | Wiki.js file assets and configuration. |
| `/docker/appdata/tripbot/` | `tripbot` | Tripbot application logs, dynamic assets, and database dumps. |
| `/docker/appdata/uptime-kuma/` | `kuma` | SQLite database storing status checks and uptime statistics. |
| `/docker/appdata/netdata/` | `netdata` | Netdata metric history and database. |

---

## 🏗️ Custom Docker Build Contexts (`/docker/custom`)

Services that use `build/custom` image specifications store their `Dockerfile` and build source files under `/docker/custom/`:

- `/docker/custom/tripbot/` — Build context for custom Tripbot container image.
- `/docker/custom/website/` — Build context for main website container image.
- `/docker/custom/calculator_benzos/` — Build context for benzo calculator app.
- `/docker/custom/calculator_volume/` — Build context for volume calculator app.

---

## 🪵 Log Directory Layout (`/docker/logs`)

Log files generated by containers are mounted to `/docker/logs/` so host monitoring services (such as Fail2ban and CrowdSec) can read them:

- `/docker/logs/fail2ban/` — Monitored by `fail2ban` service.
- `/docker/logs/crowdsec/` — Web access logs parsed by `crowdsec`.
- `/docker/logs/traefik/` — Traefik access and error logs.
- `/docker/logs/nginx/` — Nginx access logs.

---

## 🔐 Security Permissions Guardrails

To prevent unauthorized access or privilege escalation:

```bash
# Ensure /docker/secrets is owned by root and readable only by root (0700)
sudo chown -R root:root /docker/secrets
sudo chmod 700 /docker/secrets

# Ensure log directory allows container log writes
sudo chmod 755 /docker/logs
```
